Current state / routing warning

The default 2B profile has Universal Memory MCP enabled. The Jarvis profile currently has no MCP configured. That means the target architecture is clear, but Jarvis is not yet an MCP-connected authority or reader. Treat the roles below as the intended boundary, not as proof of a completed connection.

01 / roles

Four layers. Four jobs.

The useful question is not which memory is “best”. It is which layer is allowed to do which job, and where a shared claim becomes governed.

Universal Memory MCP authority

A governed, structured cross-agent record store with namespaces, revisions, provenance and proposals. Shared facts require Danny approval. It is the durable authority layer—not a scrapbook and not a prose wiki.

shared facts

Jarvis curation

The Hermes profile and knowledge-vault gatekeeper. Jarvis validates, classifies and curates human-readable Markdown wiki pages so people and agents can understand the governed record.

clear explanations

Daz Memory ingestion

An ingestion and context pipeline. It can collect, shape and supply leads, but it is not authority for shared facts. A lead still needs the governed path before it becomes durable truth.

context in

Hermes built-in memory local

Profile-local context for an agent’s continuity and working state. It is useful inside that profile, but it is not shared authority across the system.

profile context

Hermes built-in memory remains beside this path: useful for profile-local context, never a substitute for the governed record.

03 / decision

Decision summary

  • UM for governed facts. The shared record needs explicit ownership, revision history, provenance and approval.
  • Jarvis for curated explanations. The wiki is the readable interpretation layer, not the authority layer.
  • Daz Memory for ingestion. Context can arrive there without silently becoming a shared fact.
  • Hermes memory stays local. Profile continuity must not be mistaken for cross-agent governance.

What this prevents

  • A prose page becoming “true” merely because it is easy to read.
  • An ingestion pipeline silently writing shared authority.
  • A profile-local memory being treated as a system-wide record.
  • Jarvis being assumed connected when its profile has no MCP configured.
04 / next steps

Make the boundary operational.

  1. Keep the default 2B profile’s UM MCP connection as the governed-facts path.
  2. When approved, configure the Jarvis profile with the appropriate restricted MCP access; until then, do not infer a live connection.
  3. Define the namespace, revision, provenance and proposal-to-approval conventions that every shared record must follow.
  4. Have Jarvis curate Markdown explanations from governed records, while keeping Daz Memory as ingestion/context rather than authority.
