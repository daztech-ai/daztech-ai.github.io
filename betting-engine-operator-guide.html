What was built

Selected-game workflow

Run one request for one game with one stake. The engine returns check, build, verify, pass, or blocked.

Product loop

This is the core operating rhythm the engine now supports.

Request

Pick a game and provide stake, sport, bookmaker, and query or event ID.

Analyze

Run PEV singles, core SGMs, optional long-shot, evidence, and drift.

Act

Open bookmaker, copy/build legs, enter exact odds, then record check, skip, or place.

Learn

Settle later and let performance tracking update trust, ROI, and calibration.

How humans use it

Danny uses the HTML page to decide what to physically check or build in the bookmaker app. The engine never places a bet.

Analyze by game queryCLI
daz-betting-engine assistant request \
  --sport rugbyleague_nrl \
  --query "Eels v Raiders" \
  --stake 20 \
  --bookmaker sportsbet \
  --output reports/operator/latest \
  --publish-dir reports/site/operator/latest
Analyze by event IDCLI
daz-betting-engine assistant request \
  --sport rugbyleague_nrl \
  --event-id EVENT_ID \
  --stake 20 \
  --bookmaker sportsbet \
  --output reports/operator/latest

Open the operator page

Use reports/operator/latest/index.html to see the verdict, action cards, evidence status, drift check, and exact odds widget.

Check the bookmaker manually

Use the bookmaker CTA and copy buttons. For SGMs, enter the exact bet-slip odds before treating anything as place eligible.

Record the action

Record checked, skipped, or placed. Static GitHub Pages mode falls back to downloadable/copyable JSONL.

Settlement and publishing commands

The feedback loop only becomes meaningful after results are recorded honestly.

Show and settle open betsCLI
daz-betting-engine performance open \
  --ledger reports/game-assistant/actions.jsonl

daz-betting-engine performance settle \
  --ledger reports/game-assistant/actions.jsonl \
  --candidate-id CANDIDATE_ID \
  --result win \
  --return-amount 17.50 \
  --note "manual Sportsbet result"
Refresh and publishCLI
daz-betting-engine performance report \
  --ledger reports/game-assistant/actions.jsonl \
  --output reports/performance/latest

daz-betting-engine product publish \
  --operator reports/operator/latest \
  --performance reports/performance/latest \
  --site-dir reports/site

How agents use it

Hermes, OpenClaw, and future agents should read JSON only. HTML is for humans.

Agent decision flow

  1. Read manifest.json.
  2. Load the latest operator_feed.json.
  3. Inspect decision.primary_action and cards[].
  4. Check drift_check.status, evidence.status, and performance.trust_state.
  5. Return CHECK, BUILD, VERIFY, PASS, or BLOCKED with the reason and required exact odds.

Decision meanings

DecisionMeaningHuman action
checkWorth checking at the bookmaker now.Open the app and confirm current odds.
buildBuild the SGM and enter exact slip odds.Do not place until exact odds clear the minimum.
verifyPossible angle but needs manual sanity check.Review evidence, drift, and price carefully.
passNo bet recommended.Save the stake.
blockedUnsafe, stale, incomplete, or negative edge.Do not bet unless a future run changes the contract.

Rules agents must obey

Never do these

  • Never auto-place bets.
  • Never treat verify as place.
  • Never place an SGM without exact bookmaker slip odds.
  • Never fabricate evidence or expert consensus.
  • Never scrape HTML for decisions.

Always preserve these distinctions

  • Long-shot tickets are separate and capped at $5.
  • Conviction try-scorers are not engine-backed +EV.
  • Checked and skipped actions are audit events, not placed bets.
  • Only confirmed place actions enter performance as open bets.
