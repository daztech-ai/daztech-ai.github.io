Mini PC bootstrap.
New agent or 2B?

A safe guide for a fast 32 GB mini PC that already has WSL and history from previous agents. Start with inspection. Do not wipe, overwrite, or accidentally create two Telegram operators.

TARGET: native Linux + WSL rollbackSOURCE: private GitHub onlySTATE: encrypted transfer onlyDEFAULT: new agent first

Choose the operating model first

00 / DECISION
RECOMMENDED START

Independent mini-PC agent

Give the mini its own identity, config, bot, ports, state, and Git workspace. Keep 2B here. Let the new agent prove itself without touching the live control plane.

  • Lowest cutover risk.
  • Allows experiments and service hardening.
  • Requires a separate Telegram bot or a non-Telegram test surface.
LATER / HIGHER RISK

Move 2B to the mini

Restore 2B's encrypted runtime state and make the mini the production control plane. Keep this machine as rollback.

  • Preserves one operational identity.
  • Requires browser auth and state migration.
  • Never run both Telegram gateways at once.
Practical recommendation: bootstrap the mini as a new agent first. Do not copy 2B's identity on day one. Once the mini is stable, decide whether it becomes a worker, a server, or the future 2B host.

1. Inventory before touching anything

01 / DISCOVER

Run read-only discovery

Previous agents may have left repos, services, ports, credentials, databases, and half-finished work. Record first. Clean later.

hostnamectl
uname -a
free -h
df -h
ls -la ~
find ~/projects -maxdepth 2 -type d 2>/dev/null | sort
systemctl --user --no-pager --type=service
ss -lntup

Make an evidence file

Save output outside Git. Include date, hostname, active services, listening ports, repo remotes, and anything that looks like an old agent.

mkdir -p ~/migration-evidence
script -q ~/migration-evidence/inventory-$(date +%F).txt
hostnamectl
systemctl --user --no-pager --type=service
ss -lntup
exit

Inventory checklist

2. Establish ownership and hygiene

02 / CONTROL

Do not wipe

Do not delete previous agents, WSL distributions, repos, profiles, databases, or services until their purpose is known and a backup exists.

Separate identities

A new mini agent needs its own name, config root, ports, logs, credentials, and Telegram bot. Shared state is how ghosts acquire production access.

Define the owner

Pick one Linux user for the stack. Enable lingering only after confirming the service model and permissions.

Hard boundary: never commit tokens, browser profiles, SQLite state, runtime databases, logs, or generated evidence to GitHub. GitHub remains source-only, even when the repository is private.
# Safe baseline. Review before running.
sudo apt update
sudo apt install -y git curl jq age rsync python3 python3-venv build-essential
loginctl enable-linger "$USER"
mkdir -p ~/projects ~/migration-evidence ~/migration-transfer

3. Bootstrap the independent agent

03 / BUILD

Give it a name decision

Example: mini-operator. Write down its role: worker, research agent, server, or future control plane. Do not call it 2B if 2B remains here.

Clone source at known commits source

cd ~/projects
git clone git@github.com:daztech-ai/2b.git 2b
 git clone git@github.com:daztech-ai/browser-scrape.git browser-scrape
 git clone git@github.com:daztech-ai/scrape-facade.git scrape-facade
 git clone git@github.com:daztech-ai/minimax-mcp-server.git minimax-mcp-server

Build environments locally reproducible

Create fresh virtual environments and install from each repository's declared dependency files. Do not copy WSL virtual environments or Node modules. Install a supported Chromium/Playwright browser for the mini's chosen browser mode.

Use portable configuration no WSL paths

Replace hard-coded paths such as /mnt/c, WSL-only Chromium locations, and Orca worktree paths with environment-driven paths under $HOME. Keep service definitions in one installable template.

Assign a non-conflicting port map isolation

The independent agent must not collide with 2B. Document every port. Bind internal services to loopback unless remote access is explicitly required.

4. Transfer state only when there is a reason

04 / MIGRATE
For a new agent: start with fresh state. Transfer only selected non-identity data, such as approved reference databases or sanitized fixtures. Do not clone 2B's credentials or Telegram identity into the new agent.

2B migration state candidates

  • Telegram/OpenClaw/Hermes credentials
  • ~/.config/2b
  • ~/.openclaw
  • ~/.hermes
  • SQLite databases and durable state
  • ~/.chromium-scrape, only if approved
  • Relevant ~/.local/state and ~/.local/share

Never transfer blindly

  • Virtual environments or node_modules
  • Browser caches and temporary files
  • Logs and generated evidence
  • WSL/Windows path assumptions
  • Unreviewed old-agent state
  • Secrets in shell history or chat
# Illustrative pattern only. Build an explicit manifest first.
find ~/.config/2b ~/.openclaw ~/.hermes ~/.local/state ~/.local/share \
  -maxdepth 2 -type f -printf '%p %m %s\\n' 2>/dev/null \
  > ~/migration-evidence/state-manifest.txt

# Encrypt an approved archive before transfer; do not improvise the file list.
tar -czf ~/migration-transfer/approved-state.tar.gz -T approved-state-files.txt
age -r <MINI_OR_OPERATOR_PUBLIC_KEY> \
  -o ~/migration-transfer/approved-state.tar.gz.age \
  ~/migration-transfer/approved-state.tar.gz
shred -u ~/migration-transfer/approved-state.tar.gz

The archive command is a pattern, not permission to transfer everything. Review the manifest, ownership, modes, and identity boundaries first.

5. Bring up and test in layers

05 / VERIFY

Base services

Network, SSH, Tailscale, time sync, systemd user manager, and backups.

Browser layer

Chromium/CDP, browser-scrape, profile permissions, and browser-health. Re-authenticate rather than forcing an incompatible profile if necessary.

Application layer

scrape-facade, MiniMax MCP, Camofox, Hermes, and OpenClaw. Start one unit at a time and inspect its journal.

Delivery layer

Telegram comes last. Use a separate test bot for an independent agent. Never start two consumers for the same production bot.

Per-service proof

systemctl --user is-active UNIT
journalctl --user -u UNIT -n 100 --no-pager
curl -fsS http://127.0.0.1:PORT/health
ss -lntup

Smoke-test checklist

6. Decide whether to promote the mini

06 / PROMOTE

Keep the independent agent

Best if the mini is useful as a worker, research box, scraper, or second operator. Keep separate identity and state permanently.

No production cutover. 2B stays here.

Promote to 2B host

Only after the mini has passed the full service and browser smoke tests and the state transfer has been rehearsed.

Stop WSL's production Telegram gateway first. Then start the mini gateway.
  1. Freeze changes and record the tested commits.
  2. Stop 2B/Hermes/OpenClaw/Telegram services on WSL.
  3. Start the mini production units.
  4. Run browser, MCP, gateway, and Telegram smoke tests.
  5. Keep WSL powered and unchanged as rollback for 1–2 weeks.

7. Rollback is a first-class operation

07 / RECOVER
Rollback trigger: broken Telegram delivery, browser auth failure, state corruption, duplicate message handling, or an unexplained service loop.
# On the mini: stop delivery first.
systemctl --user stop 2b-telegram-gateway.service

# On the current WSL host: restore the known-good production plane.
systemctl --user start hermes-gateway.service
systemctl --user start openclaw-gateway.service
systemctl --user start 2b-telegram-gateway.service
systemctl --user is-system-running
systemctl --user --failed

Do not delete the mini state after a failed cutover. Preserve logs and evidence, then repair the failed gate deliberately.

8. The promotion gate

08 / DONE MEANS
Starting position: build the mini as an independent agent with fresh state. Preserve 2B here. Promotion is optional, later, and earned by evidence.
