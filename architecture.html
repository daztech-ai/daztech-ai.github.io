From raw data to a daily betting card — Daz in one page

Daz is a multi-sport betting engine that scrapes free data, models probability, applies a hard risk gate, and publishes a daily card to GitHub Pages. Every pick is auditable, every stake is sized, and nothing reaches a card without passing 13 safety gates.

Build status · ~80% of vision live · racing & NRL production, NBA/MLB in progress

2What's actually built, stage by stage

🌐

1. Data Sources

10 live
  • HKJC, GoBet — HK racing tips & cards
  • Racing Australia — acceptances + results (8 states)
  • Racing & Sports — speedmaps (BABS)
  • Harness.org.au, TheDogs — BABS-driven
  • NBA, NRL, MLB, Football (EPL/CSV)
All free. No paid odds feed. Server-rendered where possible.
🕷️

2. Scrapers + BABS

Built
  • run_scrapers.py — 10 registered sources, one CLI
  • 21 Python modules in src/scrapers/
  • BABS = Browser Agent Bridge. Firefox+Edge via CDP. Replaces 5+ years of Selenium pain.
  • TokenJuice compression opt-in for LLM-friendly output
3 cron scrapes/day: 8am HKJC, 8pm Thu GoBet, 8pm Fri acceptances.
🗄️

3. Database

Schema v3
  • SQLite, WAL mode, 16 MB at data/betting.db
  • 8 sports tables · 4 racing tables · scrape_log
  • Conventions: team_name, league_code, runner_id nullable
  • Backtest data: 11,940 historical results
One DB = one source of truth. No CSV sprawl.
🧠

4. Models

Most built
  • Racing — 7-factor aggregator (form, speed, class, barrier, weight, connections, track-fit) + Phase 3 calibration (Bayesian blend, Monte Carlo, XGBoost)
  • NRL — 5 modules: team ratings, try-scorer, margin, SGM builder, props
  • NBA — ad-hoc game scripts (G6, G7). No reusable pipeline yet.
  • MLB — pitcher strikeout model (AUC 0.916), daily picks
Isotonic calibration. 8% edge threshold (racing), 5% (sports). ML: XGBoost on engineered features.
🛡️

5. Risk Gate

Built
  • RiskManager in src/engine/execution/risk.py
  • 13 gates: kill switches, jurisdiction, venue allowlist, bankroll, loss limits, drawdown
  • Every decision → JSONL audit log
  • No LLM anywhere in the kill chain (deterministic only)
A model can be 100% right and still be blocked here. Bankroll > conviction.
📒

6. Jarvis Ledger

Built
  • src/output/jarvis_ledger.py — ledger builder
  • Per-bet: pick, market, price, model prob, edge, stake (Kelly), conviction tier, timestamp
  • Output: JSONL + per-day JSON in output/ledgers/
  • Feeds: backtest, tax reports, ROI dashboard
A bet that wasn't in Jarvis didn't happen. That's the rule.
📱

7. Cards → GitHub Pages

Built
  • src/output/unified_card.py — single card for racing/NRL/NBA
  • Hub-first: index.html lists all cards, mobile-first, why-toggle on every pick
  • src/publish/github_pages.py — git push = live
  • 35+ cards already published. Auto-refresh every 5 min.
Domain: daztech-ai.github.io. CNAME configured.

6TL;DR

What's real today: an end-to-end pipeline that scrapes 10 sources, models probability for racing & NRL, runs every pick through a 13-gate risk gate, writes a JSONL ledger, and publishes mobile cards to a live hub. Cron-driven, audit-logged, with zero paid data.

What it proves: the architecture is sound. The data layer, the modelling surface, the risk gate, and the publishing loop are all production-shaped. We can swap any stage without breaking the others.

What it doesn't prove yet: that the model consistently beats the market over a large sample. We have the data, the backtest harness, and the ledger to find out — we just haven't run that final test.

What would unlock the next chapter: a 30-day backtest of the settled ledger against closing odds, then a paid channel (Telegram or web) that turns the engine into a product.
