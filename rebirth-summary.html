3. What got built (6 subsystems)

3.1 Bonus-bet pipeline

Pure-Python, Decimal-based EV calculator for "1 leg fail = bonus bet back" promos. Two functions: calculate_bonus_bet_ev() and optimal_stake_under_promo() (quarter-Kelly with 5% bankroll cap). CLI renders a card in daztech-pages mobile-first style.

Files: src/daz_betting_engine/bonus_bet/{conversion.py, cli.py}

3.2 Live data — Odds API + Edge bridge

Edge bridge extension installed in Chrome. BABS command aliases (babs_eval, babs_snapshot) work via extension service worker. --my-offers mode scrapes 16 live Neds offers. CachedOddsService wraps The Odds API v4 with budget tracking + 401/402 distinction (401 = bad key, fail fast; 402 = real quota, 24h backoff).

Files: src/daz_betting_engine/odds_api/{client.py, cached_service.py}, src/daz_betting_engine/bonus_bet/offer_scraper.py

3.3 WC international Poisson model (v3)

Trained on 2014/2018/2022 World Cups (333 matches parsed, 206 deduped with proper home_team). All WC matches marked home_advantage=neutral (FIFA 2022/2018/2026 venues are neutral for both teams). Predictions: Brazil-Germany 45/26/28, Spain-Curaçao 49/26/25.

Files: scripts/wc_train_v3.py, data/wc_training/international_state_v3.json

3.4 Daily loop + card renderers

scripts/daily_loop.py runs 7 stages: scrape Neds → render My-Offers card → render WC Tomorrow → render NRL Tomorrow → push to daztech-pages (with git sync) → Telegram alert. Card renderers: wc_tomorrow.py, nrl_tomorrow.py, sgm_tomorrow.py. All mobile-first styled, daztech-pages-compatible.

Files: scripts/daily_loop.py, src/daz_betting_engine/cards/*.py

scripts/matchday.py exposes three subcommands: build (call daily_loop), review (T-1h late-mail — fetch live odds via Odds API, compare to card, flag >10% line moves), notify (T-30m Telegram alert with BET/PASS call). schedule subcommand prints review+notify times for the day. NO crons — invoke manually or wire to Windows Task Scheduler.

Files: scripts/matchday.py

5. Lessons learned

The big one: the model correctly said "no bet on 2% edge" for singles, but the parlay multiplier (3 legs at 1.66 × 2.37 × 1.36 = 5.35x) is what made small-edge markets profitable. For multi bets, lower the per-leg threshold from 3-5% to 1-2% since the multiplier covers the variance. For SGMs (correlated legs like BTTS + WDW + Margin), the model is even less useful — those are by-eye structures where a one-sided game gives you all three legs.

5.1 The 401 vs 402 bug

The Odds API was returning 401 (Unauthorized, bad key) but our code treated it as a hard quota block, triggering a 24-hour local backoff. Fixed: _is_auth_error() detects 401 separately, fails fast with a clear error message, and clears the budget cache so a fresh error shows up after key rotation.

5.2 AEST vs UTC dates

Originally _today_iso() returned UTC date, which rolled to the next day at 14:00 UTC (= midnight AEST). Cards were getting dated 2026-06-17.html when it was already 2026-06-18 in AEST. Fixed: _today_iso() now uses AEST (UTC+10).

5.3 Git ordering in daily loop

Old code copied cards first then reset to origin/main, wiping the copies. New code syncs git first (fetch + reset --hard origin/main + stash safety), then copies cards, then commits. Stash dropped after sync.

5.4 Hallucinated cards

Multiple parallel sessions generated 6 cards with hallucinated fixtures (Czech/Swiss/Canada/Qatar/Mexico on Thu 18 Jun, when those are actually on Fri 19 Jun). Deleted from daztech-pages live site. Root cause: the other-Daz-agent's SOUL.md had a non-existent assistant request command in its Betting Engine Consult Rule, so it hallucinated fixtures instead of reading the cached cards. Patched SOUL.md to point at the actual file paths. New handover doc HANDOFF-2026-06-18-mavis-daily-loop.md gives the receiving agent the source-of-truth paths.

5.5 No crons

Daz said it clearly after a hallucinated cze-rsa cron ran every 30 min looking for a match that didn't exist: "I dont want any crons like this, they just cause pain." All scheduled automation is invoke-only. matchday.py review and matchday.py notify are tools Danny runs at the right time, or wires to Windows Task Scheduler on his own machine where he can see and kill every task.

6. Quick start (5 minutes)

Step 1: SSH into the betting server and activate the venv. 
cd /home/daz/projects/daz-betting-engine
source .venv/bin/activate  # or use .venv/bin/python directly
Step 2: Run the daily loop to build today's cards. 
.venv/bin/python scripts/daily_loop.py
Outputs 3 cards (My Offers, WC Tomorrow, NRL Tomorrow) to ~/.openclaw/workspace-baccs/, updates index.html, git commits + pushes to daztech-ai/daztech-ai.github.io (served by Cloudflare Worker at daztech.dazworkbench.workers.dev).
Step 3: Check the cards. Open: 
https://daztech.dazworkbench.workers.dev/index.html
Click into each card to see the by-eye leans, line moves, and stake suggestions.
Step 4: For each match, decide: place bet, or pass. Update the BY_EYE dict in cards/wc_tomorrow.py or cards/nrl_tomorrow.py with your lean if you have one.
Step 5: After each match settles, update the bets ledger: ~/.openclaw/workspace-baccs/bets-{YYYY-MM-DD}.json with the final score, leg results, and your P&L.

7. Daily loop

7.1 When to run

Once per day, ideally 18:00-22:00 AEST (so cards are ready for evening/morning review before tomorrow's matches).

7.2 What it does

  1. Scrapes Neds offers via Edge bridge (13-16 live offers)
  2. Renders my-offers-{date}.html
  3. Renders wc-tomorrow-{date}.{md,html} for tomorrow's WC fixtures
  4. Renders nrl-tomorrow-{date}.{md,html} for tomorrow's NRL fixtures
  5. Copies all to ~/.openclaw/workspace-baccs/
  6. Updates index.html with new card links
  7. Git: fetch origin/main, reset hard, copy cards, add+commit+push
  8. Sends Telegram alert to Danny (chat_id 676224220) — graceful no-op if no token

7.3 Flags

FlagEffect
--dry-runRender cards, skip git commit/push. Useful for verifying.
--no-telegramSkip Telegram alerts even if token is set.

7.4 Bankroll display

The engine does NOT assume a bankroll. By default, cards show stakes as percentages ("2% of bankroll"). To show dollar amounts, set:

export BET_BANKROLL_AUD=1000
.venv/bin/python scripts/daily_loop.py
# Now cards show "2% ($20)" instead of just "2%"

This is per-session. The env var is read by _get_bankroll() in each card renderer.

8. Matchday cadence (3 stages)

8.1 Stage 1: Build (T-24h+)

Run daily_loop.py in the evening before match day. Or rely on the cron if you set one up.

8.2 Stage 2: Review (T-1h, lineups announced)

For each match starting in ~1h:

.venv/bin/python scripts/matchday.py schedule --date 2026-06-19
# output: review at 04:00 AEST, notify at 04:30 AEST for Switzerland-Bosnia

.venv/bin/python scripts/matchday.py review --match "Switzerland vs Bosnia & Herzegovina"
# fetches live odds from Odds API, compares to card line, flags >10% moves
# logs to data/logs/daily_loop.log

Output example:

[review] Switzerland vs Bosnia & Herzegovina
  kickoff (AEST): Fri 19 Jun 05:00
  current lean:   Switzerland @ 2% of bankroll
  card line:      {'home': 1.61, 'draw': 4.2, 'away': 6.6}
[review] fetching live odds from Odds API...
[review] live line:    {'home': 1.61, 'draw': 4.3, 'away': 6.6, ...}
[review] line moves: {'home': 0.0, 'draw': +2.4%, 'away': 0.0}
[review] no significant line moves — call unchanged

8.3 Stage 3: Notify (T-30m, final BET/PASS)

For each match starting in 30 min:

.venv/bin/python scripts/matchday.py notify --match "Switzerland vs Bosnia & Herzegovina"

Sends to Danny on Telegram (via OpenClaw gateway):

⏰ 30 min to Switzerland vs Bosnia & Herzegovina
  Kickoff: 05:00 AEST
  Lean:    Switzerland
  Call:    BET ($20 on 1.61)
  Book:    betfair_ex_au
  Source:  wc-tomorrow-2026-06-18.md

8.4 When to wire Windows Task Scheduler

Open Task Scheduler → Create Task. For each match with a real lean:

  • Trigger: at the review time (T-1h)
  • Action: wsl -e bash -c "cd /home/daz/projects/daz-betting-engine && .venv/bin/python scripts/matchday.py review --match 'Switzerland vs Bosnia & Herzegovina'"
  • Trigger: at the notify time (T-30m)
  • Action: same with notify instead of review

Recommendation: start with one task — daily build at 18:00 AEST — and add per-match review/notify tasks only for matches with a real lean.

9. Adding leans to BY_EYE

When you have a real lean for a match (not just Watch/Skip), add it to the BY_EYE dict in the relevant card module:

9.1 WC

# src/daz_betting_engine/cards/wc_tomorrow.py
BY_EYE = {
    "Switzerland vs Bosnia & Herzegovina": {
        "lean": "home",  # "home" | "draw" | "away" | "watch" | "skip"
        "rationale": "Why this lean...",
        "stake_pct": 0.02,  # 0.0 to 1.0
    },
    # ...
}

9.2 NRL

# src/daz_betting_engine/cards/nrl_tomorrow.py
BY_EYE = {
    "Wests Tigers vs Dolphins": {
        "lean": "home",  # "home" | "away" | "watch" | "skip"
        "rationale": "...",
        "stake_pct": 0.02,
    },
}

After editing, the next daily_loop.py run will use the lean.

9.3 Default by-eye behavior

If a match isn't in BY_EYE, the renderer uses:

  • Skip if any side is < 1.30 (heavy favorite, no value)
  • Watch otherwise (competitive, you decide)

10.2 Get final scores

For WC, fastest is web_search for "match name final score WC 2026". For NRL, use FOX Sports boxscore URLs. For other sports, use the source you trust most.

10.3 Update card edge stats

After a day's settling, look at the pattern:

  • Did Skip verdicts hold? (Match went as expected, no value missed)
  • Did Watch verdicts produce edge? (Coin-flip went your way?)
  • Did MARGINAL verdicts lose? (Bank on the model's discipline)

If a pattern emerges (e.g. "MARGINAL bets lose more than they win"), consider raising the per-leg threshold for singles.

11. Troubleshooting

SymptomLikely causeFix
git push failed: remote is ahead You pushed to daztech-pages between daily loop runs cd ~/.openclaw/workspace-baccs && git pull origin main, then re-run daily_loop
No fixtures cached for tomorrow Odds API cache is stale Run scripts/refresh_odds.py to fetch fresh data
Odds API key rejected (401) Key is bad/revoked Get new key from dashboard, run scripts/rotate_odds_api_key.py --new <key>
Odds API quota exhausted (402) Hit monthly plan ceiling Wait until next cycle, or upgrade plan
No Telegram bot token found OpenClaw gateway not injecting token Check ~/.openclaw/.env or gateway config
live odds fetch failed Network down or API timeout Re-run; cached cards still work
Cards show old fixtures GitHub Pages CDN cache Wait 60s for propagation; filename change (-v2) busts cache
Tests failing after a change Regression in renderer or matchday logic Run .venv/bin/python -m pytest -v, find the failing test, fix

13.2 Next product direction

Phase 1: Player stats database (1-2 days)

Build a player-level database from Wikipedia goal-scorer data. For each player: goals, assists, shots, cards per game. Output: data/players/wc_2026_player_stats.json.

Phase 2: Bayesian-shrunk player ratings (1 week)

For each player, estimate true goal-scoring rate with regression to a prior: true_rate = (n_goals + prior_count × prior_rate) / (n_games + prior_count). Prior from historical WC data (2014/2018/2022 in the engine). Critical for small-sample players.

Phase 3: Player-prop cards (2 weeks)

For a player facing a specific opponent, predict expected props: expected_goals = player_attack × opponent_defense × minutes_factor. Same Dixon-Coles logic as WC v3, but per-player. New card type: wc-player-props-{date}.html.

Phase 4: GPU fine-tuning (1 month)

Fine-tune a local model on the 4080 GPU to produce human-readable reasoning layers for bet cards (the "why this bet" paragraph, like Oddjam does). Nutz's secondary model.

13.3 Lessons to bake into the model

For multi bets, lower the per-leg threshold from 3-5% to 1-2% since the parlay multiplier covers the variance. For SGMs with correlated legs (BTTS + WDW + Margin on a one-sided game), the model is even less useful — by-eye structures only.
